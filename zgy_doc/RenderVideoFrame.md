# RenderVideoFrame 中的 memcpy 详解

> 本文分析的是**重构前**的代码，用来讲清 stride 原理。当前代码有三处变化：源行宽优先取 `pImage->pLineSize[0]`、每行只拷 `width * 4` 字节、行数取图像高度和缓冲区高度的较小值；另外不录像时会跳过这段 memcpy，由 `sws_scale` 直接写入窗口缓冲区。详见 `NativeRender.md`。

## 代码

```cpp
for (int i = 0; i < m_DstHeight; ++i) {
    memcpy(dstBuffer + i * dstLineSize,
           pImage->ppPlane[0] + i * srcLineSize,
           srcLineSize);
}
```

---

## 拆解三个参数

```cpp
memcpy(
    dstBuffer + i * dstLineSize,          // ① 写到哪里（目标地址）
    pImage->ppPlane[0] + i * srcLineSize, // ② 从哪里读（源地址）
    srcLineSize                           // ③ 读写多少字节
);
```

---

## 具体数字示例

假设视频是 **4×3 像素**（极度简化），RGBA 格式，stride = 6（硬件对齐后）：

```
srcLineSize = 4 × 4 = 16 字节（每行4个像素，每像素4字节）
dstLineSize = 6 × 4 = 24 字节（stride=6，每行比实际多2个像素的填充空位）
```

### 源图像在内存里的布局（紧密连续，无填充）

```
字节偏移  0: [像素(0,0)][像素(1,0)][像素(2,0)][像素(3,0)]   ← 第0行，16字节
字节偏移 16: [像素(0,1)][像素(1,1)][像素(2,1)][像素(3,1)]   ← 第1行，16字节
字节偏移 32: [像素(0,2)][像素(1,2)][像素(2,2)][像素(3,2)]   ← 第2行，16字节
```

### 目标缓冲区在内存里的布局（每行末尾有硬件填充）

```
字节偏移  0: [    ][    ][    ][    ][填充][填充]   ← 第0行，24字节
字节偏移 24: [    ][    ][    ][    ][填充][填充]   ← 第1行，24字节
字节偏移 48: [    ][    ][    ][    ][填充][填充]   ← 第2行，24字节
```

---

## 循环每次做了什么

```
i=0：从源偏移  0 读16字节 → 写到目标偏移  0
目标第0行：[像素(0,0)][像素(1,0)][像素(2,0)][像素(3,0)][填充][填充]  ✅

i=1：从源偏移 16 读16字节 → 写到目标偏移 24
目标第1行：[像素(0,1)][像素(1,1)][像素(2,1)][像素(3,1)][填充][填充]  ✅

i=2：从源偏移 32 读16字节 → 写到目标偏移 48
目标第2行：[像素(0,2)][像素(1,2)][像素(2,2)][像素(3,2)][填充][填充]  ✅
```

每次循环只拷贝一行的有效像素，**跳过目标行末尾的填充空位**，让下一行落在正确的位置上。

---

## 如果不用循环，直接一次性 memcpy 会怎样？

```cpp
// 错误写法
memcpy(dstBuffer, pImage->ppPlane[0], 3 * srcLineSize);
```

源数据是连续的48字节，目标每行却有24字节的空间，一次性塞进去会这样：

```
目标第0行：[像素(0,0)][像素(1,0)][像素(2,0)][像素(3,0)][像素(0,1)][像素(1,1)]  ❌ 第1行头两个跑这里了
目标第1行：[像素(2,1)][像素(3,1)][像素(0,2)][像素(1,2)][像素(2,2)][像素(3,2)]  ❌ 全错位
目标第2行：[空][空][空][空][空][空]                                              ❌ 第2行没写进来
```

结果：画面向左错位、花屏。

---

## 为什么目标缓冲区每行末尾会有填充？

这是 GPU/显示硬件的**内存对齐要求**。

硬件访问内存时，要求每行的起始地址必须是某个值（如64字节、128字节）的整数倍，这样可以提高内存带宽利用率。当视频宽度不满足对齐要求时，系统自动在行末填充空字节，使每行总长度达到对齐值。

```
例：视频宽100像素，硬件要求对齐到128像素

stride = 128
每行实际占用：128 × 4 = 512 字节
其中有效像素：100 × 4 = 400 字节
末尾填充：     28 × 4 = 112 字节（不对应任何画面内容）
```

`stride` 就是这个对齐后的行宽（单位：像素），由系统/驱动决定，代码不能假设 `stride == width`。

---

## 补充：源图像也可能有填充

上面假设源图像每行紧挨着排列（`srcLineSize = width * 4`）。但如果源图像来自 FFmpeg（`AVFrame` / `av_image_alloc`），它的每行也可能按 16、32、64 字节对齐，
这时源也有填充，`srcLineSize` 应该用图像自带的行宽（`pLineSize[0]`），而每行实际拷贝的字节数仍是 `width * 4`：

```cpp
int srcLineSize = pImage->pLineSize[0] > 0 ? pImage->pLineSize[0] : pImage->width * 4; // 源步进
int copyBytes   = pImage->width * 4;                                                    // 每行有效像素
memcpy(dstBuffer + i * dstLineSize, pImage->ppPlane[0] + i * srcLineSize, copyBytes);
```

三个量各管一件事：**源步进**、**目标步进**、**每行拷多少**，不要混用。

---

## 一句话总结

> 源图像每行**紧挨着**排列，目标缓冲区每行末尾有**硬件填充的空位**，所以必须逐行拷贝，每次跳过那段空位，把下一行数据放到正确的位置。
