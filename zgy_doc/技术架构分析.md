## 1. 项目概述

### 1.1 项目定位
LearnFFmpeg 是一个专注于 Android 平台音视频开发的教学项目，通过 FFmpeg 库实现了完整的音视频播放、录制、编辑功能。

### 1.2 核心功能
- 多种渲染方式的视频播放器（ANativeWindow、OpenGL ES、VR 3D）
- 音频播放与可视化
- 视频录制与编码（支持 H.264）
- 音频录制与编码（支持 AAC）
- GLSL 滤镜（相机预览与录制）
- 音视频同步（视频同步到音频主时钟）
- 硬件解码支持（MediaCodec）
- 流媒体播放

### 1.3 技术指标
- **最小 SDK**: Android 6.0 (API 23)
- **目标 SDK**: API 36
- **支持架构**: ARM64-v8a, ARMv7
- **NDK版本**: r21e（21.4.7075529）
- **编译工具**: CMake 3.22.1（CMakeLists 声明最低 3.4.1）
- **FFmpeg**: 4.2，以静态库（`.a`）形式放在 `jniLibs/`，另含 x264、fdk-aac

### 2.2 设计模式应用

#### 2.2.1 策略模式（Strategy Pattern）
- **应用场景**: 渲染器的选择
- **实现**:
  - 抽象接口: `VideoRender`, `AudioRender`
  - 具体策略: `NativeRender`, `VideoGLRender`, `VRGLRender`, `OpenSLRender`
  - 动态切换不同的渲染实现

#### 2.2.2 模板方法模式（Template Method）
- **应用场景**: 解码器基类
- **实现**: `DecoderBase` 定义解码流程框架
  - `Init()` - 初始化
  - `DecodingLoop()` - 解码循环（模板方法）
  - `OnFrameAvailable()` - 具体子类实现

#### 2.2.3 单例模式（Singleton）
- **应用场景**: GL渲染器
- **实现**: `VideoGLRender::GetInstance()`, `VRGLRender::GetInstance()`

#### 2.2.4 包装器模式（Wrapper）
- **应用场景**: 播放器统一接口
- **实现**: `PlayerWrapper` 统一封装 `FFMediaPlayer` 和 `HWCodecPlayer`

#### 3.1.2 FFMediaPlayer 核心实现

```cpp
// 文件: app/src/main/cpp/player/FFMediaPlayer.cpp

void FFMediaPlayer::Init(JNIEnv *jniEnv, jobject obj,
                         char *url, int videoRenderType, jobject surface) {
    // 1. 创建解码器
    m_VideoDecoder = new VideoDecoder(url);
    m_AudioDecoder = new AudioDecoder(url);

    // 2. 根据渲染类型创建渲染器（策略模式）
    if(videoRenderType == VIDEO_RENDER_OPENGL) {
        m_VideoDecoder->SetVideoRender(VideoGLRender::GetInstance());
    } else if (videoRenderType == VIDEO_RENDER_ANWINDOW) {
        m_VideoRender = new NativeRender(jniEnv, surface);
        m_VideoDecoder->SetVideoRender(m_VideoRender);
    } else if (videoRenderType == VIDEO_RENDER_3D_VR) {
        m_VideoDecoder->SetVideoRender(VRGLRender::GetInstance());
    }

    // 3. 创建音频渲染器
    m_AudioRender = new OpenSLRender();
    m_AudioDecoder->SetAudioRender(m_AudioRender);

    // 4. 设置回调
    m_VideoDecoder->SetMessageCallback(this, PostMessage);
    m_AudioDecoder->SetMessageCallback(this, PostMessage);
}
```

#### 3.1.3 解码器架构（DecoderBase）

**核心成员变量**（节选）:
```cpp
class DecoderBase : public Decoder {
protected:
    AVFormatContext *m_AVFormatContext;  // 封装格式上下文（音频、视频解码器各自打开一份）
    AVCodecContext  *m_AVCodecContext;   // 解码器上下文
    AVPacket        *m_Packet;           // 编码数据包
    AVFrame         *m_Frame;            // 解码后的帧

    std::atomic<int64_t> m_CurTimeStamp; // 当前帧显示时间（毫秒，已减去 start_time）
    int64_t m_StartTimeStamp;            // 系统时钟参考下的播放起点（毫秒）
    int64_t m_Duration;                  // 总时长（毫秒）

    int  m_StreamIndex;                  // 流索引
    std::atomic<int>   m_DecoderState;   // 解码器状态（跨线程读写）
    std::atomic<float> m_SeekPosition;   // 待执行的 seek 目标，-1 表示无

    thread *m_Thread;                    // 解码线程
    mutex m_Mutex;                       // 保护状态切换
    condition_variable m_Cond;           // 暂停时阻塞等待，不轮询
    AVSyncCallback m_AVSyncCallback;     // 读取主时钟（音频时钟）的回调
};
```

**解码流程**（简化）:
```cpp
void DecoderBase::DecodingLoop() {
    for(;;) {
        {
            unique_lock<mutex> lock(m_Mutex);
            if(m_DecoderState == STATE_PAUSE)          // 暂停：在条件变量上等待
                m_Cond.wait(lock, [this]{ return m_DecoderState != STATE_PAUSE; });
            if(m_DecoderState == STATE_STOP) break;
        }
        // 内部依次：执行待处理的 seek → av_read_frame → send_packet（EAGAIN 时先取帧再重送）
        // → receive_frame → AVSync() 等待或丢帧 → OnFrameAvailable() 渲染
        // 读到 EOF 后送空包，把解码器里剩余的帧全部取出
        if(DecodeOnePacket() != 0) {
            // 文件已读完且解码器已排空：进入暂停，等待 seek 或退出
            m_DecoderState = STATE_PAUSE;
        }
    }
}
```

### 3.2 录制模块（Recorder Module）

#### 3.2.1 录制架构

三种录制器互相独立，由 `MediaRecorderContext` 按录制类型创建其中一个，用 `shared_ptr` 持有：

```
MediaRecorderContext（JNI 入口，按类型选择录制器）
        │
        ├── SingleVideoRecorder  只录视频（相机画面 → H.264，无 x264 时退回 MPEG4）
        ├── SingleAudioRecorder  只录音频（PCM → AAC）
        └── MediaRecorder        音视频合成（H.264 + AAC → MP4）

GLCameraRender：相机预览渲染 + 滤镜；录制时从 FBO 回读 RGBA 画面，回调给录制器
```

回调线程（GL 线程、AudioRecord 线程）在锁内拷贝录制器的 `shared_ptr`，到锁外再调用，停止录制时对象不会被提前销毁。

#### 3.2.2 MediaRecorder 核心实现

**初始化流程**（省略错误处理，实际每一步失败都会释放已分配的资源）:
```cpp
int MediaRecorder::StartRecord() {
    // 1. 分配输出格式上下文（按文件后缀推断格式）
    avformat_alloc_output_context2(&m_FormatCtx, NULL, NULL, m_OutUrl);

    // 2. 添加音视频流
    AddStream(&m_VideoStream, &m_VideoCodec, m_OutputFormat->video_codec);
    AddStream(&m_AudioStream, &m_AudioCodec, m_OutputFormat->audio_codec);

    // 3. 打开编码器；打开之后再 avcodec_parameters_from_context 拷贝参数到流
    //    （MP4 需要 AV_CODEC_FLAG_GLOBAL_HEADER，x264 使用 ultrafast + zerolatency）
    OpenVideo(m_VideoCodec, &m_VideoStream);
    OpenAudio(m_AudioCodec, &m_AudioStream);   // 同时创建 AVAudioFifo

    // 4. 打开输出文件并写文件头
    avio_open(&m_FormatCtx->pb, m_OutUrl, AVIO_FLAG_WRITE);
    avformat_write_header(m_FormatCtx, nullptr);

    // 5. 音频、视频各启动一个编码线程
    m_pVideoThread = new thread(VideoEncodeThread, this);
    m_pAudioThread = new thread(AudioEncodeThread, this);
}
```

**入队**:
```cpp
int MediaRecorder::OnFrame2Encode(NativeImage *inputFrame) {
    // 1. 从复用池取一块缓冲（池大小 4），拷贝图像，记录采集时间作为 pts
    VideoFrame *frame = ObtainVideoFrame(inputFrame->width, inputFrame->height, inputFrame->format);
    NativeImageUtil::CopyNativeImage(inputFrame, frame);
    frame->timestamp = GetSysCurrentTime() - m_StartTime;

    // 2. 推入有界队列（上限 15 帧），满了挤出最旧的一帧回收
    VideoFrame *dropped = m_VideoFrameQueue.Push(frame);
    if(dropped) RecycleVideoFrame(dropped);
    return 0;
}
```

**编码线程**：用 `WaitPop` 阻塞等待数据（不轮询）；音频先写入 `AVAudioFifo`，凑满编码器要求的帧长再编码，pts 按累计采样数计算；两路线程写文件时由 `m_WriteMutex` 串行。

### 3.3 渲染模块（Render Module）

#### 3.3.1 渲染器类型

| 渲染器 | 类型 | 应用场景 | 实现方式 |
|--------|------|---------|---------|
| NativeRender | 视频 | 原生窗口渲染 | ANativeWindow |
| VideoGLRender | 视频 | OpenGL渲染 + 滤镜 | OpenGL ES 3.0 |
| VRGLRender | 视频 | VR 全景播放 | OpenGL ES 3.0 球面映射 |
| OpenSLRender | 音频 | 音频播放 | OpenSL ES |
| AudioGLRender | 音频 | 音频可视化 | OpenGL ES 3.0 |

#### 3.3.2 VideoGLRender 实现细节

**OpenGL 渲染流程**:
```
1. EGL 环境由 Java 层 GLSurfaceView 创建，Native 层只在
   OnSurfaceCreated / OnSurfaceChanged / OnDrawFrame 回调中执行 GL 调用
   （每次 OnSurfaceCreated 都是新上下文，旧的纹理/程序 ID 要清零重建）

2. 编译着色器（GLSL ES 3.0），缓存 uniform 位置

3. 纹理上传
   ├── 解码线程 RenderVideoFrame() 只在锁内拷贝图像并置"脏"标记
   └── GL 线程 OnDrawFrame() 中仅在脏时上传：
       尺寸/格式不变用 glTexSubImage2D，变化时重新 glTexImage2D

4. 片元着色器中按格式采样（RGBA / I420 / NV21 / NV12），YUV → RGB

5. GLSurfaceView 负责 eglSwapBuffers
```

**YUV 转 RGB 着色器**（I420 分支，节选）:
```glsl
#version 300 es
precision highp float;
in vec2 v_texCoord;
uniform sampler2D s_texture0;   // Y
uniform sampler2D s_texture1;   // U
uniform sampler2D s_texture2;   // V
out vec4 outColor;

void main() {
    vec3 yuv;
    yuv.x = texture(s_texture0, v_texCoord).r;
    yuv.y = texture(s_texture1, v_texCoord).r - 0.5;
    yuv.z = texture(s_texture2, v_texCoord).r - 0.5;
    vec3 rgb = mat3(1.0,     1.0,      1.0,
                    0.0,    -0.344,    1.770,
                    1.403,  -0.714,    0.0) * yuv;
    outColor = vec4(rgb, 1.0);
}
```

### 3.4 公共模块（Common Module）

#### 3.4.1 AVPacketQueue（数据包队列）

**功能**: 线程安全的 AVPacket 缓冲队列，目前由 `HWCodecPlayer` 使用（读包线程生产，音频/视频解码线程消费）

**核心实现**:
```cpp
class AVPacketQueue {
public:
    enum PacketType { PACKET_DATA, PACKET_FLUSH, PACKET_EOS };

    int  PushPacket(AVPacket *pkt);   // av_packet_move_ref 转移所有权，调用方无需再 unref
    void PushFlushPacket();           // seek 后插入，解码线程见到它就 flush 解码器
    void PushEOSPacket();             // 文件读完后插入，解码线程见到它就开始排空
    // 返回 1 取到包；0 非阻塞且队列为空；-1 已 Abort
    int  GetPacket(AVPacket *pkt, PacketType *type = nullptr, bool block = true);
    void Abort();                     // 唤醒所有等待者，Stop 时调用，线程不会卡死

private:
    struct Node { AVPacket *pkt; PacketType type; };
    std::queue<Node> m_Queue;
    std::mutex m_Mutex;
    std::condition_variable m_Cond;
};
```

#### 3.4.2 其他公共组件

| 组件 | 作用 |
|------|------|
| `ThreadSafeQueue<T>` | 全部访问加锁；可设容量上限（满了挤出最旧元素交给调用方释放）；`WaitPop(timeoutMs)` 阻塞取出；`WakeUpAll` 用于停止 |
| `SyncClock` | 线程安全的时钟，支持暂停冻结、重置，无效时返回 -1 |

#### 4.3.2 同步机制

**条件变量 (condition_variable)**:
```cpp
condition_variable m_Cond;

// 生产者
{
    unique_lock<mutex> lock(m_Mutex);
    m_Queue.push(data);
    m_Cond.notify_all();  // 通知消费者
}

// 消费者
{
    unique_lock<mutex> lock(m_Mutex);
    while(m_Queue.empty()) {
        m_Cond.wait(lock);  // 等待数据
    }
    data = m_Queue.pop();
}
```

## 6. 关键技术实现

### 6.1 音视频同步

#### 6.1.1 同步策略

常见的同步方式有三种：视频同步到音频、音频同步到视频、同步到外部时钟。**本项目实现的是视频同步到音频**，音频不可用时视频退回系统时钟。

**音频时钟**来自 `OpenSLRender` 中正在播放的那一帧：该帧 pts + 从它开始播放到现在的时间（不超过帧时长）；暂停时冻结。
目前没有扣除声卡输出延迟，画面可能比声音早几十毫秒。

**视频侧同步**（`DecoderBase::AVSync`，简化）:
```cpp
// 返回 false 表示这一帧应当丢弃
bool DecoderBase::AVSync() {
    if(m_MediaType == AVMEDIA_TYPE_AUDIO)
        return true;   // 音频不睡眠：渲染器的有界队列满了会阻塞写入，节奏由声卡决定

    int64_t masterClock = m_AVSyncCallback(m_AVDecoderContext);  // 音频时钟，-1 表示不可用
    int64_t diff = (masterClock >= 0)
                 ? m_CurTimeStamp - masterClock                              // 对齐音频
                 : m_CurTimeStamp - (GetSysCurrentTime() - m_StartTimeStamp); // 退回系统时钟

    if(diff > 0) {                       // 视频超前：等待，单次最多 100ms，下一帧继续校正
        av_usleep(min(diff, DELAY_THRESHOLD) * 1000);
        return true;
    }
    return diff >= -DROP_THRESHOLD;      // 落后超过 100ms：丢帧追赶
}
```

#### 6.1.2 PTS（Presentation Time Stamp）处理

```cpp
void DecoderBase::UpdateTimeStamp() {
    // best_effort_timestamp 是 FFmpeg 推算出的显示时间戳；
    // pkt_dts 是解码时间戳，有 B 帧时与显示顺序不一致，不能用于同步
    int64_t ts = m_Frame->best_effort_timestamp;
    if(ts == AV_NOPTS_VALUE) ts = m_Frame->pts;
    if(ts != AV_NOPTS_VALUE) {
        int64_t ms = av_rescale_q(ts, stream->time_base, AVRational{1, 1000});
        // 减去文件起始时间（TS 文件常从非 0 开始），音视频用同一个基准
        if(m_AVFormatContext->start_time != AV_NOPTS_VALUE)
            ms -= m_AVFormatContext->start_time / 1000;
        m_CurTimeStamp = ms;
    }
}
```

### 6.3 硬件加速解码

#### 6.3.1 MediaCodec 硬解码流程

> 本项目 `HWCodecPlayer` 的做法：FFmpeg 负责解封装；H.264/H.265 的包经 `h264_mp4toannexb` / `hevc_mp4toannexb` bsf 转成 Annex-B；
> `AMediaFormat` 由流参数构建，csd-0/csd-1 从 bsf 输出的 extradata 中拆出；拿不到输入缓冲时保留这个包下一轮再送；
> 读到文件末尾送 `END_OF_STREAM` 并排空输出；seek 时由解码线程自己 `AMediaCodec_flush`。

```cpp
// 1. 创建 MediaCodec
AMediaCodec *codec = AMediaCodec_createDecoderByType("video/avc");

// 2. 配置
AMediaCodec_configure(codec, format, surface, NULL, 0);

// 3. 启动
AMediaCodec_start(codec);

// 4. 解码循环
while(decoding) {
    // 获取输入缓冲区
    ssize_t idx = AMediaCodec_dequeueInputBuffer(codec, timeout);
    if(idx >= 0) {
        // 写入编码数据
        uint8_t *buf = AMediaCodec_getInputBuffer(codec, idx, &bufsize);
        memcpy(buf, data, size);
        AMediaCodec_queueInputBuffer(codec, idx, 0, size, pts, 0);
    }

    // 获取输出
    idx = AMediaCodec_dequeueOutputBuffer(codec, &info, timeout);
    if(idx >= 0) {
        // 渲染到 Surface
        AMediaCodec_releaseOutputBuffer(codec, idx, true);
    }
}
```

## 7. 性能优化策略

> 说明：本节多为通用优化思路，**大部分没有在本项目中实现**。项目里实际用到的有：
> - 视频帧缓冲复用池（`MediaRecorder`，池大小 4）；
> - 有界队列：`ThreadSafeQueue` 容量上限、`OpenSLRender` 最多缓存 3 帧、`HWCodecPlayer` 按缓冲时长限流；
> - 条件变量阻塞等待，取代 `usleep` 轮询；
> - 软解多线程（`thread_count = 0`）；
> - ANativeWindow 渲染且不录像时，`sws_scale` 直接写入窗口缓冲区，省去一次拷贝；
> - 相机渲染只在录制时才从 FBO 回读像素，回读缓冲复用。

### 7.1 内存优化

#### 7.1.1 对象池模式

```cpp
// AVFrame 对象池
class FramePool {
private:
    queue<AVFrame*> m_FrameQueue;
    mutex m_Mutex;

public:
    AVFrame* Acquire() {
        unique_lock<mutex> lock(m_Mutex);
        if(m_FrameQueue.empty()) {
            return av_frame_alloc();
        }
        AVFrame* frame = m_FrameQueue.front();
        m_FrameQueue.pop();
        return frame;
    }

    void Release(AVFrame* frame) {
        av_frame_unref(frame);
        unique_lock<mutex> lock(m_Mutex);
        m_FrameQueue.push(frame);
    }
};
```

    long currentTime = getCurrentTime();
    long deltaTime = currentTime - lastFrameTime;

        lastFrameTime = currentTime;

}

## 总结

### 项目优势

1. **架构清晰**: 分层明确，模块解耦，易于扩展
2. **功能完整**: 涵盖播放、录制、滤镜等核心功能
3. **性能考虑**: 独立解码线程、MediaCodec 硬解、有界队列与缓冲复用
4. **跨平台**: 基于 FFmpeg，易于移植
5. **代码质量**: 注释详细，命名规范，设计模式应用合理

### 技术亮点

1. **多种渲染方式**: ANativeWindow、OpenGL ES、VR
2. **音视频同步**: 视频同步到音频时钟，落后丢帧、超前等待
3. **硬件加速**: MediaCodec 硬解码支持
4. **实时滤镜**: GLSL 着色器滤镜（相机预览与录制）
5. **线程安全**: 跨线程状态用 atomic，队列加锁并可被唤醒退出

### 适用场景

- Android 音视频开发学习
- 短视频、直播应用开发
- VR 全景视频播放
- 音视频编辑应用
- 流媒体播放器开发

### 扩展方向

1. **功能扩展**
   - 添加更多滤镜效果
   - 支持多轨道音视频
   - 实现画中画模式
   - 添加字幕支持

2. **性能优化**
   - 使用 Vulkan 替代 OpenGL
   - 优化内存分配策略
   - 实现零拷贝数据传输

3. **平台扩展**
   - 移植到 iOS 平台
   - 支持 Windows/Mac 桌面端
